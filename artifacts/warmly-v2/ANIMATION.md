# Система анимаций

Анимации в Warmly существуют, чтобы интерфейс ощущался живым и мягким,
а не чтобы привлекать внимание к себе. Ни одна анимация не должна
быть замечена как "эффект" — только как естественность перехода.

## Инструмент: встроенный `Animated`, не `reanimated`

Осознанный выбор. У приложения скромные анимационные потребности —
плавное появление, лёгкий сдвиг, мягкая пружина при нажатии — без
жестовых анимаций на UI-потоке и сложных хореографий, ради которых
имеет смысл подключать `react-native-reanimated` с его нативной
конфигурацией и отдельным babel-плагином. Встроенный `Animated`
достаточен, ничего не добавляет в зависимости и соответствует
принципу "минимальное количество зависимостей" из ТЗ.

## Структура

```
src/theme/tokens/animation.ts   Данные: длительности, кривые Безье,
                                   конфигурация пружины (уже было + добавлена SPRING_CONFIGS)

src/animation/
  useReducedMotion.ts            Системная настройка "уменьшить движение"
  easing.ts                       Конвертация кривой из токена в Animated.Easing
  useSpringValue.ts                Общий строительный блок для пружинных анимаций
  useFadeTransition.ts              fade
  useScaleTransition.ts              scale (появление)
  useSlideTransition.ts               slide
  useSoftPress.ts                      soft spring (обратная связь на нажатие)
  index.ts

src/components/animation/
  FadeView.tsx                    Декларативная обёртка над useFadeTransition
  ScaleView.tsx                     Декларативная обёртка над useScaleTransition
  SlideView.tsx                      Декларативная обёртка над useSlideTransition
  PressableScale.tsx                  Замена Pressable с useSoftPress
  index.ts
```

Два слоя неслучайно разделены:

- **`src/animation/`** — хуки. Возвращают `Animated.Value` / стиль,
  ничего не рендерят сами. Нужны, когда анимируемое значение должно
  сочетаться с чем-то ещё специфичным для конкретного будущего
  компонента (например, анимация роста дерева, управляемая логикой
  `treeGrowthService`, а не просто `visible`).
- **`src/components/animation/`** — готовые обёртки `<FadeView>`,
  `<ScaleView>`, `<SlideView>`, `<PressableScale>` для стандартного
  случая "просто анимированно показать/скрыть/нажать". Это и есть
  прямой ответ на "Components should not duplicate animation code":
  будущему экрану, которому нужно плавное появление, никогда не
  придётся писать `Animated.timing` — только обернуть содержимое в
  готовый компонент.

## Четыре типа перехода — и почему именно так реализован каждый

**Fade (`useFadeTransition` / `<FadeView>`).**
Простейший и самый частый переход — только `opacity`, `Animated.timing`
с кривой `standard`. Длительность по умолчанию — `fast` (150ms):
достаточно, чтобы не быть рывком, и достаточно быстро, чтобы не
ощущаться как задержка.

**Scale (`useScaleTransition` / `<ScaleView>`).**
Появление сопровождается lлёгким увеличением от `0.96` до `1` —
специально небольшая амплитуда: карточка, "выскакивающая" из 0.5,
выглядит игриво и противоречит требованию "avoid flashy effects";
едва уловимое увеличение читается как мягкое появление. Scale всегда
анимируется вместе с `opacity` от одного `progress`-значения — чистый
scale без сопутствующего fade на глаз читается как рывок геометрии, а
не как плавный переход.

**Slide (`useSlideTransition` / `<SlideView>`).**
Небольшое смещение (12dp по умолчанию) в одну из четырёх сторон,
тоже вместе с `opacity` по той же причине, что и scale. Дистанция
сознательно маленькая: элемент не "въезжает" через весь экран, а
слегка сдвигается — это разница между "спокойным" и "заметным"
переходом.

**Soft spring (`useSoftPress` / `<PressableScale>`).**
Единственный пружинный профиль на всё приложение —
`SPRING_CONFIGS.soft` (`theme/tokens/animation.ts`): умеренное
демпфирование, без "дребезжания" и заметного перелёта после
нажатия. Используется для тактильной обратной связи на кнопках и
карточках — уменьшение на `0.97` при нажатии, что почти незаметно
глазу, но ощутимо как отклик.

## Все четыре — на одном фундаменте

`useFadeTransition`, `useScaleTransition`, `useSlideTransition`
устроены одинаково: `Animated.Value` от 0 до 1, `Animated.timing` с
длительностью и кривой из токенов, интерполяция в нужный визуальный
эффект. `useSoftPress` — тоже на общем строительном блоке
(`useSpringValue`), который в будущем можно переиспользовать для
любой другой пружинной анимации, не завязанной конкретно на нажатие.

Это не совпадение, а требование архитектуры: длительности и кривые
существуют строго как токены (`theme/tokens/animation.ts`), и ни один
из четырёх хуков не задаёт число или кривую самостоятельно — как и
цвета в `theme/`, как и отступы. Одна и та же логическая ошибка (два
похожих перехода с разной "скоростью на глаз" из-за того, что кто-то
написал число прямо в компоненте) здесь так же невозможна, как и с
цветами в теме.

## Reduce Motion — не опция, а встроенное поведение

Каждый из четырёх хуков внутри проверяет `useReducedMotion()` и, если
пользователь включил системную настройку "уменьшить движение",
применяет конечное состояние мгновенно (`.setValue(...)`), без
интерполяции — не ускоряет анимацию, а убирает её. Это заложено на
уровне хуков, а не оставлено на усмотрение будущего компонента: любой
код, использующий `useFadeTransition`/`<FadeView>` и так далее,
автоматически уважает эту настройку, ничего дополнительно не
реализуя.

## Пример использования (когда появятся экраны)

```tsx
import { FadeView, PressableScale } from "@/components/animation";

<FadeView visible={hasEntryToday}>
  <EntryCard entry={todayEntry} />
</FadeView>

<PressableScale onPress={handleSave}>
  <SaveButtonContent />
</PressableScale>
```

Ни `Animated`, ни `theme.animation.durations`, ни `Easing` в самом
экране не появляются — вся работа уже сделана в `src/animation/` и
`src/components/animation/`.

## Что проверено

`npx tsc --noEmit` проходит без ошибок для всего модуля анимаций.
