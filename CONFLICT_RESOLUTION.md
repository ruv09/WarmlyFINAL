# Почему конфликт может оставаться и как исправить

Если в PR всё ещё показывается конфликт, обычно причина в одном из пунктов:

1. **Ветка PR не обновлена последним коммитом** (локально исправили, но не запушили).
2. **Конфликт есть в другой ветке/PR**, а не в текущем `work`.
3. **GitHub сравнивает другую базовую ветку** (base branch changed).
4. **Конфликт в merge-коммите**, который не был завершён (`git merge --continue`).

## Проверка локально

```bash
git status
rg -n '^<<<<<<<|^=======|^>>>>>>>' App.js src backend
npm run check:conflicts
```

## Как исправить правильно

```bash
# 1) Обновить базу
git fetch origin
git checkout <your-feature-branch>
git merge origin/main

# 2) Разрешить конфликт в файлах вручную
# удалить маркеры <<<<<<< ======= >>>>>>>

# 3) Проверить, что маркеров больше нет
npm run check:conflicts

# 4) Зафиксировать и отправить

git add -A
git commit -m "Resolve merge conflicts"
git push
```

## Если конфликт виден только в GitHub UI

- Нажмите **Update branch** или заново `merge/rebase` с актуальным `main`.
- Убедитесь, что смотрите именно тот PR/ветку, куда отправлен последний коммит.
